# Appendix C - Repository reuse audit and file-level migration table

Project: `Fiscal_Deficit` (EU-27 country-year panel 1995-2023; scheduled elections x ageing -> CAPB, which can be negative).
Audit date: 2026-10-10. Method: live GitHub API (`gh api repos/andrm101/<slug>`, git trees API, compare API) and `git ls-remote`; local checks used only `rev-parse`, `hash-object`, `status --porcelain`, `log -S`, `grep`. No fetch/pull/checkout/commit was run in any source repo.

Verification method for Step 2: for every candidate path the remote git blob SHA (from `GET /repos/andrm101/<slug>/git/trees/main?recursive=1`, `truncated=false` for all seven trees) was compared with `git hash-object` of the local file. Identical blob SHA proves identical bytes, so the local copy was read as the authoritative content. Result: **29 of 29 candidate paths are byte-identical remote vs local** (eu-innovation-panel has a single workflow file, `.github/workflows/ci.yml`; nuclear-sector `weekly_pipeline.yml` was not a candidate).

**Headline finding: no candidate file is a clean direct copy.** Every file needs at least a path/constant change (1995-2023, EU-27, Slovenia, negative CAPB, project paths), and most carry a defect listed below. The closest to "copy with minimal edits" are `seed_check.py`, `infra/db/bootstrap.py` and `scripts/run_r_stages.py` (all still need renames and small fixes).
